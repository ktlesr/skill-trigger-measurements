## 1. `marketingskills` — collision

14 of 50 skills from coreyhaines31/marketingskills 2.11.1 (`5b2c000`), loaded
together as one plugin. Expected winner per case taken from the skills' own
cross-references ("For popup copy, see popups"), not my opinion.

- `--fast` v1 first (57 attempts), then full v2 (200 attempts, $10.18).
- **49 of 50 activations reached the expected skill.** One leak: a newsletter
  form reached `signup` instead of `cro`.
- **7 of 13 skills never activated on their own cases.** Displaced by the base
  model doing the work directly (93 of 120 such attempts wrote files).
- **`product-marketing` fired 0 / 200.** Its context file is read in 17/50
  activations vs 14/150 without. A positioning change went to a new
  `POSITIONING.md` in 9/10 attempts, leaving `.agents/product-marketing.md`
  stale.
- v2 added a neutral ICP case to rule out v1's wording steering toward host
  memory. It did not change the result.

## 3. `hallmark` — ablation

Nutlope/hallmark 1.1.0 (`13ac0ec`), MIT. Arm A the skill, arm B an empty plugin
of the same name. Same suite file, fixtures, prompts, model, N, mode.

- **Feasibility first, before code.** The skill has a rule list
  (`anti-patterns.md`, `slop-test.md`) but no executable detector. 14 tells
  turned into regexes: 8 literal (the skill defines them as code), 6 proxy.
  No LLM judge.
- **Calibration against its own 18 showcase pages** caught two wrong regexes
  (`z-index` matched 999; `hover_scale` couldn't see "universal") — and showed
  the showcase breaking two of its own literal rules (italic headers 8/18,
  pure `#fff`/`#000` 7/18). Kept in its own report section.
- **Round 1, organic prompts:** hallmark activated **0 / 12**. Shape did not
  hold, so no full run. A 3-attempt named check activated 3/3.
- **Round 2, "Use the hallmark skill." in both arms** (arm B asks for a skill
  that is not installed — stated before the results), 100 attempts, $7.63:
  - pure `#fff`/`#000`: **100% → 50%** of pages, intervals separate, **holds
    under a worst-case bound**.
  - `transition: all`: 35% → 57%, written with hallmark's own tokens; that rule
    lives only in `anti-patterns.md`.
  - **0 attempts to read `anti-patterns.md` / `slop-test.md`**, where 12 of the
    14 tells are defined. 3 reads of `macrostructures.md`, all refused.
  - **12 / 40 invocations stopped at the design-context gate** and built
    nothing, though every brief answered its questions.

## Decisions worth remembering

- **Expected winners from the skills' own descriptions**, so a "wrong winner"
  is the skill's routing, not my judgement.
- **Did not run the full hallmark round when round 1 showed 0 activations** —
  it would have measured the base model twice. Asked before redesigning.
- **Worst-case bound for the arm that built fewer pages**, rather than
  comparing 28 pages with 40 and calling it done.
- **`**/*.html` + `**/*.css`, never `**/*`** for content checks: the skill
  writes `.hallmark/*.json` notes that could name tells and would have biased
  only arm A.
- **Committed to `master` directly**; issue drafts link to `blob/master/...`.
