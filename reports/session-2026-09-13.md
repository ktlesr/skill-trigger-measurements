## 1. Phrase-binding experiment — feasibility, stopped before code

Asked: arm A with a `CLAUDE.md` (jimy-r's standing rule + a two-column table
for the 14 skills, rows in our cases' wording) inside the isolated
`CLAUDE_CONFIG_DIR`; arm B as today. v3 suite, `@ktlsr/assay@0.4.4`, `--fast`.

**Not possible on 0.4.4 as specified.** Read from the installed package
(`@ktlsr/assay-adapters/dist/claude-code/adapter.js`):

- `start()` creates the config dir with `mkdtemp(tmpdir(), 'assay-cc-')` per
  attempt, spawns `claude` immediately, and `finalize()` deletes it. Nothing
  is written into it and there is no hook to do so.
- The CLI passes only `permissionMode` / `allowBypassPermissions` to the
  adapter. The agent environment is an allowlist, so `CLAUDE_CONFIG_DIR`
  cannot be redirected from outside.

Workarounds considered and why they are not the asked-for arm:

- **Project `CLAUDE.md` in the fixture** (works on 0.4.4): different scope; the
  file sits in the workspace, visible and editable; the positioning case sent
  10/10 to host memory in v2, `CLAUDE.md` included, so a workspace
  `CLAUDE.md` is a direct target for one of the seven never-firing skills'
  cases; `trigger.negative.unrelated.slow_query` has no fixtures, so arm A would
  lack the file on that case unless the suite changes.
- **Plugin `SessionStart` hook**: changes the plugin under test (skill hash) and
  is a different mechanism.

**jimy-r's own placement is not the config dir.** `META_ARCHITECTURE.md`
§Command Shortcuts: "A verbal-shortcut table in the **workspace CLAUDE.md**";
`samples/CLAUDE.md.example` is `<Your name>'s workspace`, with a `CLAUDE.md`
per subproject beneath it. That is project scope, loaded from the working
directory and its ancestors — not `~/.claude/CLAUDE.md`.

That scope is reachable on 0.4.4 with no code change: the runner makes each
workdir with `mkdtemp(os.tmpdir())`, and `TEMP`/`TMP` are on the adapter's
env allowlist. Point `TEMP` at `<armA>/tmp` with the table at `<armA>/CLAUDE.md`
and every attempt's workdir has it as an ancestor — the workspace-above-project
layout jimy-r describes. Outside the workdir, so not in Glob results and not
editable under `acceptEdits`; present on the no-fixture case too; suite, skill,
fixtures and runner byte-identical. Arm B: the same redirect with no file.
**Unverified:** that the `claude` binary loads an ancestor `CLAUDE.md` under an
isolated `CLAUDE_CONFIG_DIR` in `-p` mode — needs one smoke attempt.

Two routes put to the user: (1) the ancestor route on 0.4.4 (faithful to
jimy-r's scope), (2) an adapter option seeding `<configDir>/CLAUDE.md`
(user scope, as first specified; new assay version, both arms on it).
Waiting on the choice.

Standing rule, verbatim from the user (jimy-r's): "On a matching phrase or a
close variant, go directly to the target with no clarifying question. For a new
target not in the map, ask once, then add a row. When there is genuine doubt
between two targets, ask." Table: `Phrase family | Target`, 2–7 phrases per
row separated by `/`, rows in our cases' wording, not his.
